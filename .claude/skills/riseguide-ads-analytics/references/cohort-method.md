# Когортний метод діагностики дня

Головне правило: **діагностувати агрегатом по когортах, ніколи —
сортуванням кампаній.** 22.08.26 акаунт втратив ~$19.2k, а найгірша окрема
кампанія була лише −$939: збиток розмазаний по сотнях лончів по $100–900,
у списку кампаній аварії не видно. Когортний roll-up знаходить її одразу.

## Вік кампанії — похідний, не зберігається

```sql
WITH first_seen AS (
  SELECT campaign_id, MIN(created_date) AS first_date
  FROM dbt_google_marts.google_ads_dashboard
  WHERE spend > 0          -- без цього guard дата когорти неправильна
  GROUP BY 1
)
-- далі DATE_DIFF(created_date, first_date, DAY)
```

Бакети: **0–3d = new, 4–10d = ramp, 11d+ = mature; PMax — окремим бакетом.**
Крос-чек: дата лончу зашита в імені кампанії (DDMMYY) — див. bigquery.md.

## Guardrail: частка лончів у бюджеті

Частка DemGen-бюджету на кампаніях віком ≤3 дні: **норма 17–34%,
>35% = тривога.** 22.08 було 44.3% — рекорд, і день закрився в нуль.
Це випереджальний індикатор — його видно вдень, до того як відомий ROI.

## Правила, виведені з кейсу 22.08

- **Поганий ROI-день при здорових юніт-метриках** (LTV/purchase — максимум
  за 3 тижні, воронка в нормі) = проблема ціни трафіку, не продукту/воронки.
- **CPM-дискримінатор:** перш ніж списувати на «ринок» — перевірити по
  каналах. 22.08: DemGen CPM $3.81→$5.25, PMax тримав $3.72. Один канал
  стабільний = це не ринок.
- **Перед фінансуванням лончів** перевірити, що mature/PMax із плюсовим ROI
  не порізані й не заморожені. 22.08: у new влили +$8.3k, mature при +30%
  порізали на −$3.8k, PMax при +30% заморожений — саме так виходить нульовий
  день.
- **Ramp, що деградує день-до-дня, ≠ «навчання»** — це якість батчу лончів.
  Батч трекати за датою лончу і судити як одиницю (батч 18.08: −31% → −45%).
